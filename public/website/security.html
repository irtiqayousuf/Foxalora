Security first

Email is personal. We protect it that way.

Foxalora can read and send your customers' email, so security isn't a feature. It's the foundation everything is built on.

Passwords never stored in plain text

Mailbox passwords are never saved in plain text, never put in the browser's storage, and never written to logs.

Encrypted end to end

HTTPS in the browser and TLS to your mail servers, with certificates checked. No silent fallback to unencrypted connections.

Safe email display

Every incoming email is treated as untrusted. Scripts and harmful code are removed, and emails are shown in an isolated, sandboxed area.

Tracking images blocked

Outside images are blocked by default, so senders can't secretly tell when someone opens their email.

Your network stays private

Users can't point Foxalora at unknown servers. Only mail servers you approve are used, which protects your internal network (SSRF protection).

Secure sessions

Secure, HttpOnly cookies, automatic sign-out after inactivity, limits on failed sign-ins and protection against forged requests.

What we store

We keep as little as possible.

Emails and attachments stay on your mail servers. Foxalora only keeps what it needs to work.

  • Preferences, contacts and signatures
  • Your admin settings and server mappings
  • Security events, without any email content

Never stored or logged

✕Mailbox passwords in plain text
✕Full email contents
✕Attachment contents
✕Session tokens in logs
Standards

Built to recognised standards.

We follow established security guidance and test before every release.

OWASP ASVS L2

The minimum security level we build and test against.

TLS 1.2+

TLS 1.3 preferred for every connection, following RFC 8314.

IMAP4rev2

Standards-based mail access, following RFC 9051.

Pen-tested

Independent penetration testing before public release.

Responsible disclosure

Found a security issue?

Please tell us privately so we can fix it before it's shared. We'll reply quickly and credit you if you'd like.
